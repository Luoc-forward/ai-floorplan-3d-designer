# AI 户型 3D 设计器

上传一张户型图，AI（火山方舟 · 豆包 doubao-seed-evolving 视觉模型）自动识别**墙体、门窗、飘窗、尺寸标注、房间语义**，秒级生成可漫游的 three.js 3D 户型；可在 2D 中校对修改户型、在 3D 中摆放/拖拽/编辑家具、更换配色、第一人称漫游，并**导出修改后的户型图（PNG / SVG / JSON）与 3D 截图**。

## 一、快速启动

环境：Python 3.8+（仅用标准库，无需 pip 安装任何东西）。

方式一（推荐）：双击项目根目录的 `启动.bat`。

方式二（命令行）：

```bash
python server.py 8765
```

然后浏览器打开 <http://localhost:8765>。

### 配置大模型（接口地址 / 模型名 / API Key）

识别能力需要火山方舟（或其他兼容 OpenAI Chat Completions 的视觉模型）凭证。**无需改代码、无需重启**，三种方式任选：

**方式一：在页面里配置（推荐）**

1. 启动后打开首页，点右上角「⚙️ 模型设置」；
2. 分别填写接口地址、模型名、API Key（输入框默认为空，需自行填写）：
   - 火山方舟示例：接口地址填 `https://ark.cn-beijing.volces.com/api/plan/v3`，模型名填你账号下可用的模型（如 `doubao-seed-evolving`）；
   - 其他兼容 OpenAI 接口格式（`/chat/completions`）的视觉模型服务，填写对应的基础地址与模型名即可；
3. 点「🔌 测试连接」验证通过后「保存设置」即可。

配置保存在服务端根目录的 `.ark-config.json`（仅本机，已在 `.gitignore`，不会提交）。

**方式二：环境变量**

- `ARK_API_KEY`：API Key
- `ARK_BASE_URL`：接口地址
- `ARK_MODEL`：模型名

**方式三（兼容旧版）**：在根目录新建 `.ark-key`，只写一行 Key。

**配置优先级**：页面保存的 `.ark-config.json` > 环境变量 > 代码内置兜底值（兜底值只含火山方舟的接口地址和模型名，**不含任何 Key**；未填写时设置页显示为空）。

> API Key 只保存在你自己运行的后端，浏览器只通过后端代理调用，不会出现在前端代码里；未配置 Key 时识别不可用，但仍可用「内置示例户型」和「空白画布手动画墙」体验全部编辑 / 3D / 漫游 / 导出功能。
>
> 仓库提供了 `config/ark-config.example.json` 作为配置字段示例；真实的 `.ark-config.json` 与 `.ark-key` 均已被忽略，不会随仓库上传。

## 二、使用流程

1. **首页上传**：点击 / 拖拽 / Ctrl+V 粘贴户型图（JPG/PNG/WEBP，≤20MB）。
   - 默认「快速模式」约 20 秒出结果；复杂图纸可勾选「AI 精修模式」（约 2~4 分钟，准确率更高）。
2. **2D 校图**：识别后自动进入。可：
   - 选择/拖动墙、门、窗、家具；拖墙端点改墙；右侧面板精确改数值；
   - 工具栏：画墙（Shift 连画正交、Alt 承重墙）、放门、放窗、📏 尺寸校准、删除；
   - 「🧲 一键方正墙体」把 AI 的轻微斜墙/碎墙强制正交合并；
   - 「显示原图」开关叠加半透明原图对照。
3. **3D 编辑**：点「生成/刷新 3D」。
   - 左键旋转、右键平移、滚轮缩放；
   - 左侧家具库**点击或拖拽**放入；3D 中直接拖动家具，选中后 `Q/E` 旋转、`R/F` 缩放，右侧面板可改尺寸/颜色/离地/复制/删除；
   - 配色 Tab：6 套全屋风格、墙漆色板、地面材质；
   - 日景/夜景、俯视/人视、天花板开关。
4. **🚶 漫游**：第一人称。
   - 桌面：`W/A/S/D` 行走、鼠标转视角、Shift 加速、点击门可开合、Esc 退出；
   - 触屏：左下虚拟摇杆移动、右侧拖动转视角；右下角小地图点击传送；
   - 带墙体/家具碰撞，不会穿墙。
5. **导出**（右上角）：
   - **修改后户型图 PNG（白底）** / **PNG（叠加原图）**；
   - **矢量户型图 SVG**；
   - **当前 3D 视图截图 PNG**；
   - **方案数据 JSON**（备份/二次开发）。

撤销/重做：`Ctrl+Z / Ctrl+Y`；删除选中：`Delete`。

## 三、目录结构

```
.
├── server.py                 # 零依赖后端：静态托管 + /api/recognize 代理豆包 + /api/config
├── 启动.bat
├── .ark-config.json         # 页面保存的模型配置（含 Key，已 gitignore，自行生成）
├── .ark-key                 # 旧版本地 Key（可选，已 gitignore）
├── config/
│   └── ark-config.example.json  # 配置字段示例（可提交）
└── web/
    ├── index.html
    ├── css/style.css
    ├── assets/              # 内置示例户型
    ├── vendor/              # three.js 本地依赖（无需联网/CDN）
    └── js/
        ├── main.js          # 主控制器：上传/视图切换/属性面板/家具库/配色/导出/快捷键
        ├── store.js         # 数据模型 + 撤销重做 + 内置两居室示例
        ├── recognizer.js    # 调后端识别 + AI 归一化结果→毫米户型(比例尺解算/房间合并)
        ├── geometry.js      # 正交轴网重建/吸附/挂接/比例尺/房间几何/开门侧判定
        ├── view2d.js        # Canvas 2D 户型编辑器（画墙/门窗/校准/拖拽/缩放平移）
        ├── view3d.js        # three.js：带洞墙体/门窗/家具/光照/漫游碰撞/小地图/截图
        ├── furniture.js     # 程序化家具库（25 件，盒子组合，无需外部模型）
        └── exporter.js      # 户型图 SVG/PNG、JSON 导出
```

## 四、数据模型（毫米，原点为户型包围盒左下，y 向上）

`walls{x1,y1,x2,y2,thick,load}`；门窗以 `wallId + off(沿墙偏移) + width` 挂在墙上；
`rooms{name,type,poly,floorColor,areaM2}`；`dims{text,x1,y1,x2,y2}`；`furniture{type,x,y,rot,sx,sy,sz,color,elev}`。
AI 返回 0~1000 归一化坐标，由 `recognizer.aiToPlan` 结合尺寸标注解算比例尺并清洗为上述模型。

## 五、技术要点

- 前端：原生 ES Module + three.js（本地 vendor，importmap），无需 npm 构建；
- AI：豆包视觉模型输出 JSON（`thinking=off + response_format=json_object`，快速且稳定）；
- 几何后处理：Manhattan 正交轴网重建、统一坐标槽闭合、共线碎墙合并、门窗最近墙挂接、客餐厅自动拼接；
- 门开向：`doorSwingSide` 依据两侧房间几何自动判定，比模型的 inward 字段可靠；
- 3D 墙体：`ExtrudeGeometry` 对门/窗洞真实开洞；漫游用墙线段 + 胶囊半径碰撞，分轴尝试实现贴墙滑动。

## 六、已知限制（后续路线）

- AI 对个别门/复杂符号存在漏识别与单次波动 → 用 2D 校图 + 一键方正兜底（产品设计上本就以「AI 出草稿 + 人工 30 秒校对」为准）；
- 暂仅承诺单层、正交户型；弧形墙、复式/楼梯、承重墙专项、手绘草图为后续项；
- 家具为程序化低模；后续可接 glTF/GLB 真实商品模型与自定义上传；
- 方案目前存于浏览器内存，刷新会丢；后续加 localStorage 草稿、云端方案与分享链接。
